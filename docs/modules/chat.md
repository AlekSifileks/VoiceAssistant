# Голосовой чат

Статус: набросок работает. «Энни, поболтаем» открывает разговор через OpenRouter. До этой фразы сеть не вызывается.

## Зачем

Отвечать голосом на обычные реплики, не смешивая их с локальными командами. Модель разговора выбирается из базы и может быть другой на одну беседу.

## Граница

Делает:

- запускает беседу фразой «{имя}, поболтаем» и заканчивает фразой «{имя}, хватит»;
- для имени «Эни» и «Энни» принимает обе записи, как их отдаёт распознаватель;
- пока беседа идёт, отправляет следующие фразы в выбранную модель вместе с предыдущими репликами;
- читает список моделей из таблицы `chat_models` в `data/assistant.db`;
- вызывает только задачу `chat` через OpenRouter.

Не делает:

- не выполняет команду с именем, в том числе без слова «пуск», и не записывает её в историю;
- не вызывает задачи `reason` и `tools`: ответ «эта задача пока не подключена», без запроса в сеть;
- не пишет историю в базу и не озвучивает ответ;
- не меняет модель по умолчанию голосом. «поболтаем с сонет» действует только до «хватит».

## Контракт

Вход: уже распознанный текст, имя и слово «пуск» из `.env`, список моделей, состояние беседы.

`chat::take` сеть не открывает. Он возвращает тишину, короткую заметку или готовые сообщения для модели. `chat::complete` выполняет задачу. Для `chat` при `CHAT_PROVIDER=openrouter` это `POST https://openrouter.ai/api/v1/chat/completions`. Ключ — `OPENROUTER_API_KEY`. Идентификатор модели из `.env` не читается.

Новая база или старая без таблицы получает две строки, и только пока таблицы ещё не было:

| phrase | model_id | По умолчанию |
| --- | --- | --- |
| быстрая | `google/gemini-3.8-flash` | да |
| сонет | `anthropic/claude-sonnet-5.5` | нет |

Нет названной модели — беседа не начинается, текущая не сбрасывается. Нет ключа — в терминал пишется `чат: нет ключа OpenRouter`, микрофон слушает дальше. Ответ модели печатается как `энни: …`. История — последние 8 пар реплик в памяти процесса.

## Где код

| Файл | Что внутри |
| --- | --- |
| `src/chat.rs` | вход в беседу, история, OpenRouter |
| `src/main.rs` | сначала команда, потом чат |
| `data/assistant.db` | таблица `chat_models` |
| `.env` | `OPENROUTER_API_KEY`, `CHAT_PROVIDER` |

Публичные точки: `chat::load_models`, `chat::take`, `chat::complete`, `chat::Config::from_env`.

## Решения

- Чат — отдельный режим, а не любая фраза с именем.
- Поставщик выбирается задачей. Адрес OpenRouter зашит только в ветке `chat` + `openrouter`.
- Стартовые модели пишутся один раз, при создании таблицы. Пустая таблица заново не заполняется.
- Неудачный запрос не попадает в историю, чтобы повтор не тащил оборванную реплику.
- «Эни» и «Энни» считаются одним именем. Другое имя из `.env` принимается только как записано.
- У `google/gemini-3.8-flash` рассуждение обязательно и входит в `max_tokens`. Для чата стоит `reasoning.effort=low` и лимит 2048, чтобы короткая фраза договаривалась до конца. Другим моделям поле `reasoning` не отправляется.

## Как проверить

Без сети:

```
cargo test --release chat::
```

Живой разговор, ключ в `.env`:

```
cargo run --release -- --language ru
```

«Энни, поболтаем» входит на модель «быстрая». «Энни, поболтаем с сонет» берёт другую модель на эту беседу. «Энни, хватит» выходит. «Энни пуск курсор» по-прежнему открывает Cursor и в чат не попадает.
