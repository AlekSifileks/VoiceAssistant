# Речь в текст

Статус: набросок работает. Закрытая фраза превращается в текст локально, строка печатается в терминал.

## Зачем

Слышать, что именно распознала GigaAM, до любого диалога. Текст никуда не отправляется.

## Граница

Делает:

- один раз поднимает процесс `stt/gigaam_server.py` и держит в нём GigaAM v3;
- принимает моно `f32` на 16 кГц — это `capture::Phrase::samples`;
- возвращает строку и время распознавания;
- отбрасывает пустой результат, строку без слов и несколько известных фраз тишины.

Не делает:

- не открывает микрофон и не решает, где фраза кончилась;
- не читает wav с диска. `--file` в `src/main.rs` — только проверка уже записанной фразы, и файл по-прежнему должен быть моно 16 кГц;
- не переводит текст и не переключает язык;
- не вызывает OpenRouter. Сеть нужна только при первой загрузке весов с Hugging Face.

Сравнение моделей — в `plan/01-rech-v-tekst.md`.

## Контракт

Вход: срез `f32`, моно, 16000 Гц. Пустой срез даёт `None`.

Выход: `Option<stt::Transcript>`.

- `Some` — непустой текст и сколько занял ответ процесса;
- `None` — тишина, строка без букв и цифр или фраза из короткого списка галлюцинаций («спасибо за просмотр», «thanks for watching», «продолжение следует», строки про субтитры).

Модель русская. `--language ru` и `--language auto` оставляют её как есть. Другой код останавливает запуск.

Оболочка вызывает `Engine::transcribe` на `Event::Phrase`, в том же потоке, который читает микрофон. Пока идёт распознавание, новые кадры могут выпасть из канала приёма. Для поочерёдных команд это нормально: следующую фразу говорят после текста.

Фраза длиннее 20 с режется на куски уже внутри расчёта и склеивается в одну строку.

## Где код

| Файл | Что внутри |
| --- | --- |
| `src/stt.rs` | процесс, запись временного wav, `transcribe` |
| `stt/gigaam_server.py` | загрузка GigaAM и ответ текстом |
| `stt/requirements.txt` | `gigaam-mlx` |
| `src/main.rs` | выбор варианта модели, печать текста, `--file` |
| `.env` | `STT_MODEL` |

Публичные точки: `stt::Config::from_env`, `stt::Engine::load`, `stt::Engine::transcribe`, `stt::DEFAULT_MODEL`.

Веса качаются в кэш Hugging Face и в git не входят. `stt/.venv` в git не входит.

## Решения

- Модель — `v3_e2e_rnnt`, порт `gigaam-mlx`. Вариант `ctc` быстрее и включается `STT_MODEL=ctc` или `--model ctc`.
- Rust не считает MLX. Расчёт — отдельный процесс на `stt/.venv`. Модель живёт в памяти между фразами.
- Временный файл фразы — моно 16 кГц, 16 бит. Дробный wav стандартный читатель Python не открывает.
- Подтверждения команд и голос чата этот процесс не произносит.
- Модель одна и русская. Команды помощника тоже русские.

## Как проверить

Без модели, только фильтр пустых фраз:

```
cargo test --release stt::
```

Первый запуск скачает веса. Интерпретатор:

```
python3 -m venv stt/.venv
stt/.venv/bin/pip install -r stt/requirements.txt
cargo run --release -- --language ru
```

После паузы в терминале строка `текст (… мс): …`.
