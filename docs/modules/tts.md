# Озвучка

Статус: набросок работает. Реплики чата говорит локальный Qwen3 женским голосом. «Готово» и «Не вышло» говорит Милена.

## Зачем

Ответ чата и исход команды должны звучать, а не только печататься. Пока звук играет, микрофон не отправляет эту речь обратно в чат.

## Граница

Делает:

- произносит удачную команду словом «Готово», неудачную — «Не вышло», системным голосом из `TTS_ACK_VOICE`;
- произносит ответ модели и короткие заметки чата локальным Qwen3-TTS;
- один раз рисует женский голос и сохраняет образец в `models/annie-voice.wav`. Дальше говорит этим файлом;
- играет звук в устройство вывода по умолчанию и возвращает управление только после конца фразы.

Не делает:

- не читает вслух строку «открыт Cursor» и другие подробности команды;
- не вызывает Piper, Silero и ElevenLabs;
- не клонирует голос человека;
- не перебивает фразу на полуслове;
- не пишет звук ответа в базу.

## Контракт

Вход: уже готовый текст. `tts::Speaker::acknowledge` берёт только успех или неудачу. `tts::Speaker::say` берёт реплику чата.

Подтверждение собирает `say -o` во временный wav и играет его общим проигрывателем. Реплика чата уходит в процесс `tts/qwen_server.py`, который держит модель в памяти и возвращает wav. Оба пути играют моно `f32`.

Пока обработчик фразы не вернулся, `capture` выбрасывает кадры, накопленные за это время. Поэтому голос колонок не становится следующей фразой.

Нет модели, нет образца или нет `tts/.venv` — текст уже напечатан, в терминал пишется `озвучка: …`, микрофон слушает дальше.

## Где код

| Файл | Что внутри |
| --- | --- |
| `src/tts.rs` | Милена, проигрыватель, связь с расчётом |
| `tts/qwen_server.py` | VoiceDesign один раз и Qwen3 Base для каждой реплики |
| `tts/requirements.txt` | `mlx-audio`, `soundfile` |
| `src/main.rs` | после печати зовёт озвучку |
| `.env` | `TTS_PROVIDER`, `TTS_MODEL`, `TTS_VOICE`, `TTS_ACK_VOICE` |

Публичные точки: `tts::Config::from_env`, `tts::Speaker::start`, `tts::Speaker::acknowledge`, `tts::Speaker::say`.

Образец голоса, каталог `models/` и `tts/.venv` в git не входят.

## Решения

- Подтверждение команды всегда одно и то же слово и всегда системный голос. Оно не ждёт Qwen.
- Голос чата — `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit`. Образец один раз делает VoiceDesign той же линейки 8-bit. Сборки с вырезанным словарём не используются.
- Rust не считает MLX. Расчёт — отдельный процесс на `tts/.venv`. Пока образец и его текст на месте, VoiceDesign не запускается.
- Описание голоса: молодая женщина, тёплый спокойный тембр, обычный русский. Ударения модель может ставить неверно.
- Другой `TTS_PROVIDER` реплики чата не произносит и пишет «эта озвучка пока не подключена».

## Как проверить

Без модели:

```
cargo test --release tts::
```

Первый запуск скачает модели и нарисует голос. Интерпретатор:

```
python3 -m venv tts/.venv
tts/.venv/bin/pip install -r tts/requirements.txt
cargo run --release -- --language ru
```

«Энни пуск курсор» открывает Cursor и говорит «Готово». Ответ после «Энни, поболтаем» печатается и произносится тем же женским голосом, что и следующий ответ.
