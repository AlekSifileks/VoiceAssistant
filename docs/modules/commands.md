# Блок команд

Статус: набросок работает. Фраза с обращением открывает Cursor, браузер или Telegram. В сеть помощник не ходит.

## Зачем

Отделить короткие локальные действия от будущего диалога. Модуль забирает только фразу, которая начинается с обращения из `.env`. Остальной текст остаётся просто текстом.

## Граница

Делает:

- читает `.env`: включён ли модуль, имя и слово запуска;
- сравнивает уже готовый текст фразы с обращением;
- открывает приложение через `open` на macOS;
- читает слова команд из таблицы `commands` в `data/assistant.db` один раз при старте;
- ищет закладку браузера в таблице `bookmarks` того же файла.

Не делает:

- не слушает микрофон и не распознаёт речь;
- не вызывает OpenRouter. Вход в чат делает модуль `chat`, не этот;
- не кликает внутри Cursor, Telegram и сайтов;
- не пишет команды и закладки после создания файла. Новая база один раз получает семь фраз (курсор, телеграм, браузер и их английские варианты) и закладку «Тимбенч» → `https://teambench.ru/`. Если рядом ещё лежит `data/bookmarks.db`, её закладки копируются в этот же момент и больше не читаются. Удалённая строка сама не возвращается.

## Контракт

Вход: строка текста одной фразы и `commands::Settings`.

Обращение — `{ASSISTANT_NAME} {COMMAND_WAKE}` после нормализации: нижний регистр, без знаков препинания. Сейчас в `.env` имя «Энни», слово «пуск». Записи «Эни» и «Энни» для этого имени равнозначны. Слово после обращения — команда, хвост — аргумент.

Слово команды ищется в загруженной таблице, не в коде. Первые строки базы:

| phrase | action | target | Хвост фразы |
| --- | --- | --- | --- |
| `курсор`, `cursor` | `open_app` | Cursor | игнорируется |
| `телеграм`, `телеграмм`, `telegram` | `open_app` | Telegram | игнорируется |
| `браузер`, `browser` | `open_browser` | пусто | имя закладки; без хвоста открывается `about:blank` |

Другое значение `action` даёт «команда не поддержана» и ничего не запускает. Адрес закладки открывается только если начинается с `http://` или `https://`.

Фраза без обращения даёт `Outcome::Ignored`: в терминал ничего дополнительно не пишется. Неизвестная команда, пустое обращение и отсутствующая закладка печатаются как `команда: …` в stderr. Успех — `команда: …` в stdout.

`.env` не перезаписывает переменные, которые уже заданы в окружении. Нет файла — модуль выключен.

## Где код

| Файл | Что внутри |
| --- | --- |
| `src/commands.rs` | разбор фразы, база, запуск `open` |
| `src/main.rs` | загрузка каталога при старте и вызов `commands::handle` после текста |
| `.env`, `.env.example` | `COMMANDS_ENABLED`, `ASSISTANT_NAME`, `COMMAND_WAKE`, необязательный `ASSISTANT_DB` |

Публичные точки: `commands::Settings::from_env`, `commands::load`, `commands::handle`.

База `data/assistant.db` и `.env` в git не входят. Образец ключей — `.env.example`.

## Решения

- Модуль включается только флагом `COMMANDS_ENABLED`. Имя и слово запуска не зашиты в коде команд.
- Одна фраза — одна команда. «Эни пуск» без слова команды ничего не открывает.
- Слова команд лежат в базе. Код знает только действия `open_app` и `open_browser`.
- Каталог команд читается один раз при старте. Закладка читается в момент команды.
- Имя закладки сравнивается целиком после той же нормализации, что и фраза. «Тимбенч» и «тимбенч» совпадают.
- URL без http(s) не открывается.

## Как проверить

Юнит-тесты не запускают приложения:

```
cargo test --release commands::
```

Живой микрофон, после строки «слушаю»:

```
cargo run --release -- --language ru
```

Скажите «Эни пуск курсор», «Эни пуск телеграм», «Эни пуск браузер» или «Эни пуск браузер тимбенч». Фраза без «Эни пуск» печатает только текст.
