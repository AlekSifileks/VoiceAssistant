# Приём голоса

Статус: набросок работает. Слушает микрофон, закрывает фразу по тишине, отдаёт сэмплы. Распознавания нет.

## Зачем

Первый шаг помощника. Пока человек говорит, процесс только копит звук. Когда фраза закрылась, следующий модуль получит уже готовый кусок, а не поток кадров.

## Граница

Делает:

- открывает входное устройство по умолчанию;
- приводит кадры к моно `f32`;
- решает, где фраза началась и закончилась;
- перед отдачей переводит фразу в моно 16 кГц.

Не делает:

- не распознаёт речь и не загружает модель;
- не открывает сеть и не вызывает OpenRouter;
- не озвучивает ответ;
- не выбирает устройство: всегда микрофон по умолчанию;
- не пишет wav. Запись файла — временная оболочка в `src/main.rs`, чтобы фразу можно было прослушать. Контракт для распознавателя — структура `Phrase` в памяти.

## Контракт

Вход: кадры микрофона в том формате, который отдал CoreAudio (`f32`, `i16` или `u16`, один или несколько каналов).

Выход: `capture::Phrase`.

- `samples` — моно `f32`, примерно в диапазоне −1..1;
- `sample_rate` — всегда 16000;
- `peak` — максимальный модуль сэмпла;
- `duration_ms` — длина уже передискретизированного буфера, вместе с коротким началом и хвостовой тишиной.

События `capture::run`:

- `Ready` — устройство открыто, в нём частота и число каналов исходного потока;
- `Listening` — раз в секунду, пока речи нет, несёт уровень последнего кадра;
- `SpeechStarted` — уровень пересёк порог;
- `Phrase` — фраза закрыта и прошла минимальную длину.

Короткая вспышка короче `min_speech_ms` не становится `Phrase`. Пока идёт речь, `Listening` не шлётся.

Оболочка `src/main.rs` печатает события в stdout и кладёт каждую фразу в `captures/phrase-NNN.wav` (32-bit float, моно, 16 кГц). Каталог `captures/` в git не входит.

## Где код

| Файл | Что внутри |
| --- | --- |
| `src/capture.rs` | устройство, нарезка, передискретизация, `probe` и `run` |
| `src/main.rs` | аргументы, печать, запись wav. Это не часть контракта |

Публичные точки: `capture::run`, `capture::probe`, `capture::Config`, `capture::Phrase`, `capture::Event`.

## Решения

- Язык процесса — Rust. Этот модуль владеет микрофоном.
- Конец фразы — тишина, а не потоковое распознавание. По умолчанию 700 мс. Порог уровня по умолчанию 0.02 RMS на кадре 20 мс. На микрофоне этого MacBook Air тишина даёт около 0.007, поэтому 0.01 уже цеплял бы шум.
- Перед порогом сохраняется 200 мс, чтобы не срезать первую согласную.
- Фраза длиннее 30 с режется принудительно: команде и реплике чата длиннее не нужно, а буфер не должен расти без конца.
- Хвостовая тишина остаётся в буфере. Распознавателю она не мешает, а обрезка по последнему громкому кадру съедает конец слова.
- Передискретизация линейная, одним проходом по уже закрытой фразе. Если на распознавании поедут согласные, менять её здесь, не в распознавателе.
- Аудиопоток не блокируется. Кадр, который не влез в канал на 64 буфера, выбрасывается.
- После события `Phrase` кадры, накопившиеся за обработку и озвучку, выбрасываются. Иначе микрофон отправил бы в чат голос из колонок.
- Остановка по Ctrl+C дописывает незакрытую фразу, если в ней уже достаточно речи.

## Как проверить

Юнит-тесты не открывают микрофон. Они гоняют нарезку на синтетическом тоне:

```
cargo test
```

Живой микрофон, одна секунда и уровень, без файла:

```
cargo run -- --probe
```

Слушать, пока не нажмёте Ctrl+C. Говорите и делайте паузу около секунды — появится wav. Текст этой фразы печатает модуль распознавания, см. `docs/modules/stt.md`:

```
cargo run --
cargo run -- --threshold 0.02 --silence-ms 800 --out captures
```

Если `--probe` пишет, что звука нет, системе не дали доступ к микрофону для терминала, из которого запущен процесс. Разрешение: Настройки системы → Конфиденциальность и безопасность → Микрофон.
